Introduction

Zeri HR is a complete HR management system built for managing employee records, attendance, leave, payroll, notices, approvals, teams, projects and role-based access control.

The system is designed for companies that need a structured HR workflow with permission-based visibility. Each user sees only the modules and records allowed by their assigned role permissions.

Installation

Local Setup

  1. Place the project folder inside the web root, for example htdocs/hr-payroll.
  2. Create a MySQL database.
  3. Copy .env.example to .env and configure database credentials.
  4. Install dependencies with Composer.
  5. Run migrations and the default admin seeder.
  6. Open the application in the browser.
composer install
php artisan key:generate
php artisan migrate
php artisan db:seed --class=AdminUserSeeder

Important Storage Commands

php artisan storage:link
php artisan optimize:clear
After changing Blade files or configuration, clear cache if the browser does not show the latest updates.

First Admin Setup After Login

After installation and AdminUserSeeder, login with the default admin account and complete the system setup before allowing employee or manager access.

Recommended Setup Order

  1. Change the default admin password from the dashboard password screen.
  2. Open Settings and update company profile, logo, favicon, contact information, timezone, currency and email settings.
  3. Create core organization records: departments, designations and reporting structure.
  4. Create salary grades with salary ranges and band names.
  5. Review default roles and permissions. Keep Admin/Super Admin full access, then adjust HR Admin, Department Head, Payroll Manager, Finance Manager and Employee roles based on company policy.
  6. Create or approve user accounts only after the employee profile is created and linked to the user account.
  7. Create employee profiles with department, designation, manager/reporting line, salary grade, employment status and linked user account.
  8. Configure leave categories, leave policies, holidays and attendance rules before employees start applying for leave or clocking attendance.
  9. Create payroll setup records: salary templates, employee salary assignments, provident fund setup, recurring deductions and opening loan records if needed.
  10. Run a small test payroll draft for one employee and review salary, deduction, loan, PF, tax and net payable before processing a full payroll run.

User Approval Rule

Registered users stay in pending_approval. Admin must create or link the employee profile first, then approve the user and assign the correct role. Approval is blocked when the user has no linked employee profile.

Do not give a user broad permissions just to make login work. Complete employee setup first, then assign the right role.

Employee Login Setup

Creating an employee profile does not automatically create login access. Login access comes from the user account, and the employee profile must be linked to that user account.

Required Workflow

  1. Go to User Management > Add User.
  2. Create a user with name, email, password and role.
  3. Use the Employee role for normal employee access, or assign another role based on your permission setup.
  4. Approve or activate the user account if approval is enabled.
  5. Go to Employees > Employee List.
  6. Edit the employee profile.
  7. In the User Account field, select the user account created earlier.
  8. Save the employee profile.
  9. The employee can now log in using the linked user email and password.

Recommended Sick, Casual and Annual Leave Setup

Leave TypeCarry ForwardEarned LeaveYear-End Behavior
Sick LeaveNoneNoUnused sick leave expires. New year starts with only the new yearly sick leave allocation.
Casual LeaveNoneNoUnused casual leave expires. New year starts with only the new yearly casual leave allocation.
Annual LeaveFull or LimitedYesUnused earned annual leave carries into the next year and is added to the new annual leave allocation.

Earned and Carry Forward Rules

  • Sick Leave: use yearly allocation, Carry Forward Mode = None, Earned Leave = No, Earned Credit Days = 0.
  • Casual Leave: use yearly allocation, Carry Forward Mode = None, Earned Leave = No, Earned Credit Days = 0.
  • Annual Leave: use yearly allocation, Carry Forward Mode = Full or Limited, Earned Leave = Yes, Earned Credit Frequency = Monthly.
  • For monthly earned annual leave, set Earned Credit Days to yearly annual leave allocation divided by 12. Example: 14 annual days / 12 = 1.17 days per month.
  • At year start, sick and casual leave balances reset to the new year allocation. Only annual leave receives carry-forward balance.

Automatic Monthly Leave Balance Sync

The system includes a scheduled leave balance sync command. It recalculates the current year leave balance for active employees, including monthly earned leave credits, so HR does not need to press the Sync button every month.

  • Scheduled command: php artisan leave:sync-balances.
  • Default schedule: last day of every month at 23:50 server time.
  • The sync is safe to rerun because balances are recalculated and updated for the year; it does not blindly add the same monthly earned leave again.
  • Manual full-year sync: php artisan leave:sync-balances 2026.
  • Manual sync for one salary grade: php artisan leave:sync-balances 2026 --salary_grade_id=3.
  • Manual sync for one employee: php artisan leave:sync-balances 2026 --employee_id=25.

Add this cron entry on the server so Laravel can run scheduled jobs:

* * * * * cd /Applications/XAMPP/xamppfiles/htdocs/hr-payroll && php artisan schedule:run >> /dev/null 2>&1

If the project path is different on production, replace the path with the production project directory.

Payroll Overview

The Payroll module manages salary structure, employee-specific salary assignment, bonuses, loans, deductions, provident fund and payslip generation.

Professional payroll flow: create salary grade, create reusable salary template, assign employee-specific salary snapshot, generate payroll draft, HR reviews, final submit, then mark payments as paid.

Payroll Flow

  1. Create Salary Grades.
  2. Create reusable Salary Templates.
  3. Assign Employee Salary from a salary template and customize the actual employee salary values.
  4. Add bonuses, loans, deductions and provident fund settings.
  5. Generate Payroll Draft for selected period. Draft shows expected salary, bonus, loan installment deduction, other deductions, PF, tax and net payable.
  6. Review all payroll items and payslips before final submission.
  7. Final Submit payroll run. This is the posting step for salary-linked records such as loan installment payment and PF contribution.
  8. Mark individual payslips as paid after payment processing.

Payroll Run Generation Logic

StepSystem Logic
Period checkThe system checks pay frequency, period start and period end. If a draft run exists for the same period, it is regenerated. If a processed run exists, only a missing selected employee can be added. Approved or paid runs cannot be regenerated.
Employee selectionIf no employee is selected, payroll is generated for all active employees. If an employee is selected, payroll is generated only for that active employee.
Salary sourcePayroll uses the employee-specific salary assignment active at the payroll period end date. If no active salary assignment exists, payroll generation stops with an error so the employee is not paid with an incorrect fallback amount.
AllowancesHouse rent, medical allowance, conveyance allowance and other allowance are taken from the employee salary assignment.
BonusBonus amount is included when the bonus date falls inside the payroll period.
Loan deductionOnly active loans are considered. Pending installments with due dates inside the payroll period are summed into the draft payslip.
Other deductionsActive employee deduction records are attached to the payslip when their effective date range is valid and their frequency matches the payroll run. One-time deductions are included only when their start date is inside the payroll period.
PF and taxEmployee PF deduction and employer PF contribution are calculated from configured percentages and the active employee basic salary. Tax is calculated from the configured tax percentage.
Draft totalsGross, deduction total and net payable are calculated for each payslip and summarized in the payroll run.
Loan balances are not reduced during draft generation. Loan installments are marked paid only when the payroll run is finalized, because the deduction becomes real only when salary is processed.

Employee Loans

The Loan module tracks employee loan requests, approval status, installment schedules and salary-based repayment.

Loan Master

  • Employee.
  • Loan reference.
  • Principal Amount.
  • Interest percentage.
  • Installment count.
  • Installment Amount, calculated from Principal Amount, Interest % and Installment Count.
  • Issued date and first installment date.
  • Status: pending supervisor, pending final, active, paused, closed or rejected.

Installment Amount Formula

The user enters Principal Amount, optional Interest % and Installment Count. The application calculates Installment Amount automatically in the form and recalculates it again on the backend when saving or rescheduling.

total_payable = principal_amount + (principal_amount * interest_percent / 100)
installment_amount = total_payable / installment_count
Principal AmountInterestInstallment CountTotal PayableInstallment Amount
60,0000%660,00010,000
60,00010%666,00011,000

Loan Approval Flow

  1. Employee submits a loan request with loan.apply or employee_loan.apply.
  2. Supervisor or department approver reviews team requests with loan.approve-supervisor or employee_loan.approve-supervisor.
  3. Final approver completes approval with loan.approve-final or employee_loan.approve-final.
  4. After final approval, the loan becomes active and installment schedules are generated.
  5. Rejected loans are stored with rejection information and are not deducted from payroll.

Loan Installments

Installments are created from the approved loan schedule. Payroll picks pending installments when their due date falls inside the payroll period.

Installment due dates are generated monthly from the first installment date. If first installment date is empty, the issued date is used as the first due date.

Salary Deduction Workflow

  1. Loan must be active before it can be deducted from payroll.
  2. Payroll draft calculates loan_deduction from pending installments due inside the payroll period.
  3. HR reviews the draft payslip and confirms that the loan deduction is correct.
  4. When HR final submits the payroll run, those due installments are marked as paid.
  5. The paid installment stores the payroll item reference so HR can see which salary/payslip paid it.
  6. When all installments are paid, the loan status becomes closed automatically.
Recommended workflow: employee applies for loan, supervisor approves, final approver activates it, payroll deducts due installments from salary, and final payroll updates loan balances.
If loan installments are manually paid, rescheduled or changed after payroll draft generation, regenerate the payroll draft before final submission so payslip deduction and loan balance remain the same.

Reschedule Rules

  • Reschedule is allowed only when no installment has been paid.
  • Reschedule recalculates Installment Amount from Principal Amount, Interest % and Installment Count.
  • The old pending schedule is deleted and a new schedule is created.
  • Reschedule is blocked after any installment is paid to protect payroll history.

Manual Installment Payment

Manual installment payment should be used only for payments collected outside salary, such as cash, bank deposit or adjustment. Salary-related repayment should normally happen through payroll finalization.

Deductions

Deductions are employee-specific amounts deducted during payroll calculation. General deductions and loan deductions are handled separately so loan balances remain accurate.

Supported Deduction Setup

  • Deduction name, such as welfare fund, penalty or advance adjustment.
  • Calculation method: Fixed Amount or Percent of Basic Salary.
  • Amount / Percent value.
  • Effective from and effective to.
  • Deduction frequency: Every Monthly Payroll, Every Weekly Payroll or One Payroll Only.
  • Reason / policy and internal notes.
  • Active/inactive status.

How Deduction Calculation Works

SetupPayroll Behavior
Fixed AmountDeducts the exact amount entered. Example: 500 deducts 500 from the payslip.
Percent of Basic SalaryDeducts the entered percent from basic salary. Example: 5 means 5% of basic salary.
Every Monthly PayrollIncluded only in monthly payroll runs while the deduction is active and inside the effective date range.
Every Weekly PayrollIncluded only in weekly payroll runs while the deduction is active and inside the effective date range.
One Payroll OnlyIncluded only when the deduction start date falls inside the payroll run period.

During payroll draft generation, matched deductions are copied into the payslip deduction breakdown and summed into other_deduction. The amount then becomes part of total_deduction and reduces net payable.

Use Employee Deductions for regular non-loan deductions such as welfare fund, penalties, advances or adjustments. Use the Loan module for installment-based employee loans because payroll will update loan installment balances after final submission.

Provident Fund

Provident Fund setup defines employee contribution percentage, employer contribution percentage, opening balance and effective date.

How PF Works

  • Employee PF % is deducted from employee basic salary and reduces net payable.
  • Employer PF % is company contribution and does not reduce employee net payable.
  • Both contributions are calculated from the active basic salary for the payroll period.
  • If salary increases through a new employee salary assignment, future payroll runs automatically calculate higher PF amounts.
  • PF setup is used when its effective date is empty or before the payroll period end date. If no PF setup is active, payroll falls back to the employee salary assignment PF percentage.
  • During final payroll submission, PF contribution transactions are posted with employee contribution, employer contribution and balance after.
  • PF transactions can be used for yearly self-service and HR reports.

Payroll Runs

Payroll run is the monthly or weekly payroll batch for one period.

Draft and Final Submission Flow

  1. HR generates payroll draft for a period.
  2. The system creates payroll items for employees.
  3. HR reviews every payroll item and payslip.
  4. If needed, HR adjusts employee salary assignment, bonus, loan, deduction or PF setup.
  5. HR regenerates draft for the same period.
  6. When everything is correct, HR clicks Final Submit.
  7. The run becomes processed, PF transactions are posted and due loan installments are marked paid against their payslips.

Payroll Calculation

Gross = basic_salary + allowance_total + bonus_total
Total Deduction = loan_deduction + other_deduction + provident_fund_deduction + tax_deduction
Net Payable = Gross - Total Deduction

Final Submit Posting Rules

  • Payroll draft can be regenerated before final submission.
  • Final submission locks the payroll run as processed.
  • Due pending loan installments in the payroll period are marked paid and linked to the employee payslip.
  • If due loan installment amounts changed after draft generation, the system blocks final submission and asks HR to regenerate the draft.
  • Provident fund contribution transactions are posted for the run.
  • After final submission, payslips can be marked as paid when salary payment is completed.
Finalized payroll runs cannot be regenerated for the same period. Create a new period or review the finalized run.

Users, Roles and Permissions

User Management controls who can access the system and what each user can do.

Users

  • Create user accounts.
  • Approve or reject user access.
  • Assign users to roles.
  • Link users with employee records.

Roles

  • The default seed creates common organization roles with practical permission assignments.
  • Super Admin and Admin receive all permissions by default.
  • HR Admin, HR Manager, Payroll Manager, Finance Manager, Department Head, Supervisor, Project Manager, Team Lead, Auditor and Employee receive scoped default permissions.
  • Admin or HR users can change the assigned permissions later from the Roles screen.
  • Users inherit access from assigned roles.

Permissions

Permissions are grouped by module, for example employee.view, payroll_run.generate, payslip.view and settings.update.

Permission access labels are database driven. Each permission stores an access scope key, label, badge class and description, so the role permission screen can show whether a permission is for own access, department/team access, admin/global access or general access.

Data Access Rules

  • Employee self-service: Employees can view their own attendance, leave applications, leave balances, assigned teams, assigned projects, assigned tasks, payslips, loans, deductions and provident fund records when the related view permission is assigned.
  • Supervisor access: Supervisors can view their own records and direct subordinate records for attendance, leave approval/reporting and task work scope. Supervisor access does not automatically expose payroll finance records.
  • Payroll privacy: Salary, payslip, loan, deduction and provident fund records are self-only unless payroll management or payroll report permissions are assigned.
  • Work module access: Team, project and task lists are scoped to records where the user is a lead, manager, member, assignee, creator or direct supervisor of an assignee. Management permissions allow wider setup access.
  • Holiday access: Users with holiday view permission can see the holiday list/calendar. Create, update and delete actions require separate holiday permissions.

Permission Assignment Rules

  • Assign one primary job role per user where possible. Do not add Employee role to HR Admin, Payroll Manager or Department Head if their role already includes self-service permissions.
  • Every staff login should be linked to an employee profile before approval, including HR Admin, Department Head, CEO/Managing Director and Payroll users.
  • Give payroll and payslip report permissions deliberately. Generic report access should not automatically mean salary access.
  • Use role.assign only for trusted administrators who can change user access.
  • Use settings.update only for users allowed to change company-wide configuration.
  • Use payroll_run.approve only for the person authorized to final submit payroll.

User Approval and Employee Setup

  1. New registered users remain in pending_approval.
  2. Admin must create or link the employee profile before approval.
  3. The employee profile stores staff identity, department, designation, reporting line, attendance scope, leave scope and payroll identity.
  4. After employee setup is complete, admin can approve the user and assign the correct role such as Employee, HR Admin, Department Head or Payroll Manager.
  5. Approval is blocked when no employee profile is linked to the user.
Do not approve a normal staff user only by assigning permissions. User account, employee profile and role assignment must all be complete before login access is activated.

How Language Selection Works

  • Users can change the interface language from the topbar language selector.
  • The selected language is stored in the session and applied through the locale middleware.
  • Translation files are stored in lang/en.json, lang/de.json, lang/fr.json and lang/hi.json.

FAQ

Can employees in the same salary grade have different salaries?

Yes. Salary Grade defines the allowed range. Employee Salary Assignment stores the actual employee-specific salary snapshot.

Does payroll use the shared salary template directly?

No. Payroll uses the employee-specific salary snapshot stored in employee_salary_templates.

Can HR review payroll before final submission?

Yes. Payroll generation creates a draft run. HR reviews the run and final submits only after checking.

Can payment be marked before payroll final submission?

No. Payslip payment can be marked only after the payroll run is finalized.

How is loan installment amount calculated?

The system calculates it from Principal Amount, Interest % and Installment Count: (principal + interest amount) / installment count. The backend recalculates it during save and reschedule.

Can a loan be rescheduled after payroll paid an installment?

No. Rescheduling is blocked after any installment is paid so payroll and loan history remain consistent.

Why can some users not see a module?

The user role may not have the required permission. Assign the needed permission from Role Permissions.
